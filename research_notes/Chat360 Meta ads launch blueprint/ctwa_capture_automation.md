## 1. First-message webhook: `referral` object, persistence, ad id → campaign/ad set mapping

### Takeaway
The first inbound message from a CTWA ad carries a `messages[0].referral` object holding the ad's `source_id` (ad ID), `source_type`, `source_url`, `headline`/`body`/media and the `ctwa_clid` click ID. Only the first message has it, so Chat360's webhook ingester must persist it on receipt, before any bot logic runs. It then resolves `source_id` → ad set → campaign through the Marketing API and stores the result on the lead.

### Cited Findings
- Meta puts a `referral` object carrying `ctwa_clid` and `source_id` inside `messages[0]` of the inbound Cloud API webhook. `ctwa_clid` appears **only on the first message** from a user, and later messages do not carry it. — [evolution-api issue #2645](https://github.com/evolution-foundation/evolution-api/issues/2645)
- Field semantics (Sinch doc mirroring Meta):
  - `headline` = the ad headline that produced the message.
  - `source_type` = the origin, `ad` or `post`.
  - `source_id` = the Facebook ID of that ad or post.
  - `ctwa_clid` = the click ID Meta generates for CTWA ads.
  — [Sinch WhatsApp message support](https://developers.sinch.com/docs/conversation/channel-support/whatsapp/message-support); [Sinch Community](https://community.sinch.com/t5/WhatsApp/What-is-Click-to-WhatsApp-and-how-does-it-integrate-with-the/ta-p/15320)
- Middleware often strips or relocates the referral. Twilio exposes it as a `ReferralCtwaClid` callback parameter, Whapi.Cloud places it at `context.ad.ctwa`, and open-source stacks (evolution-api, OpenClaw, Typebot) have open issues about it being dropped. — [Twilio changelog](https://www.twilio.com/en-us/changelog/new--click-id--callback-parameter-for-inbound-whatsapp-messages-); [Whapi blog](https://whapi.cloud/blog/track-click-to-whatsapp-ctwa-clid); [OpenClaw #39037](https://github.com/openclaw/openclaw/issues/39037); [Typebot #1906](https://github.com/baptisteArno/typebot.io/issues/1906)
- If a chat has no referral, treat its source as "unknown", not "organic". — search summary of [Whapi blog](https://whapi.cloud/blog/track-click-to-whatsapp-ctwa-clid) / [metricfixer](https://metricfixer.com/publications/analytics-conversion-tracking/track-click-to-whatsapp-ads-campaign-ad-creative-without-website)
- The `ctwa_clid` is generated by Meta and cannot be fabricated. Send it **un-hashed** to CAPI, unlike email or phone. — [metricfixer](https://metricfixer.com/publications/analytics-conversion-tracking/track-click-to-whatsapp-ads-campaign-ad-creative-without-website); [CustomerLabs blog](https://www.customerlabs.com/blog/how-to-connect-ctwa-chats-to-ad-campaigns-and-crm/)
- Marketing API mapping:
  - The Ad object exposes `id, name, status, effective_status, adset_id, campaign_id, creative`, and `/{ad-id}/insights` is available per ad. — [Meta ads-action-stats reference](https://developers.facebook.com/docs/marketing-api/reference/ads-action-stats/); [Adverity connector docs](https://docs.adverity.com/reference/connectors/connector-facebook-ads.html)
  - CTWA ads appear as regular ads with `destination_type=WHATSAPP`. — [claudeskills meta-ads](https://claudeskills.info/skill/meta-ads/) (third-party)
- Ad-side metrics:
  - The insights action type for CTWA conversations is `onsite_conversion.messaging_conversation_started_7d` ("Messaging Conversations Started").
  - `onsite_conversion.messaging_first_reply` is "New Messaging Conversations".
  — [Meta ads-action-stats reference](https://developers.facebook.com/docs/marketing-api/reference/ads-action-stats/)
- The `welcome_message` referral field: no search result confirmed it (gap; see below).

### Inferences
- **Persistence design:** On webhook receipt, before handing off to the AI agent, idempotently write a `ctwa_click` row keyed on `wamid`. Columns:
  - `wa_id` (E.164), `phone_number_id`, `waba_id`, `received_at`
  - `source_id` (ad_id), `source_type`, `source_url`, `headline`, `body`, `media_type`, `image_url`/`video_url`/`thumbnail_url`
  - `ctwa_clid`, `welcome_message_text`, `raw_referral_json`
- Then upsert the same fields onto the Zoho Lead as custom fields (`Ad_ID`, `CTWA_CLID`, `CTWA_First_Msg_At`, etc.).
- Keep `raw_referral_json` so that new Meta fields can be backfilled later.
- **Enrichment job:** Call `GET /{ad_id}?fields=name,adset_id,campaign_id` (or nested `adset{name},campaign{name}`, which is unverified syntax). Cache per ad_id, because there are only a few dozen ads in a $23k flight, and write `Campaign_Name`, `AdSet_Name`, `Ad_Name` to the lead. This lets Zoho Analytics group chats → qualified → deals by ad without a join to Meta at query time.
- Because Chat360 is its own BSP, it controls the raw webhook. The "stripped referral" failure mode of third-party middleware is avoidable, but the AI-agent/inbox layer must be checked for whether it passes the referral through.
- Repeat clickers: the same `wa_id` clicking a second ad sends a new first message with a new referral, so store **all** referrals (one-to-many). Choose first-touch versus last-touch at reporting time.

### Gaps
- **[UNVERIFIED – prior knowledge]** Full referral field list per Meta's Cloud API webhook reference: `source_url`, `source_id`, `source_type` (`ad`|`post`), `body`, `headline`, `media_type` (`image`|`video`), `image_url`, `video_url`, `thumbnail_url`, `ctwa_clid`, and a `welcome_message.text` object added around 2024–25. The live Meta page could not be fetched to confirm the exact current field set.

- Exact nested-field syntax for ad → ad set/campaign names in one Graph call was not confirmed.

## 2. WhatsApp Flows for qualification, launching from the CTWA welcome message, and interactive-message alternatives

### Takeaway
- A CTWA ad's welcome message can carry a Flow CTA, but per Meta's ads docs only a **static, single-screen Flow with no data_exchange** (Flow JSON version > 5.1).
- A multi-screen, endpoint-driven qualification Flow must therefore be sent by the bot as the first reply (a free-form interactive `flow` message inside the 72h free-entry window).
- Endpoint-based Flows require RSA-OAEP(SHA-256) key unwrapping plus AES-GCM payload encryption with a flipped IV.

### Cited Findings
- Meta's "Ads that click to WhatsApp" developer docs describe a `page_welcome_message` object with formats for (a) an ice-breaker greeting and (b) a WhatsApp Flow CTA ("Apply now"-style button tied to a flow ID). The Flow format supports only **WhatsApp Flows version > 5.1, a single screen and no data exchange**, with a limited component set. — [Meta: Ads that Click to WhatsApp](https://developers.facebook.com/documentation/ads-commerce/marketing-api/ad-creative/messaging-ads/click-to-whatsapp)
- Ice breakers are set per ad in Ads Manager as greeting prompts. Phone-number-level ice breakers are a separate feature: up to 4, 80 characters each, no emoji. — [Chatbotscape glossary](https://chatbotscape.com/glossary/click-to-whatsapp-ads)
- A sequence or Flow used by an active ad is locked, so you cannot delete or change it while the ad runs. — [WUSeller](https://www.wuseller.com/whatsapp-business-knowledge-hub/whatsapp-welcome-message-sequence-api-ads-integration/)
- The phone number in the ad must match the one linked in the automation, otherwise the flow is not triggered. — [Alibaba Cloud Chat App guide](https://www.alibabacloud.com/help/en/chatapp/use-cases/how-to-create-click-to-whatsapp-ads)
- After a user clicks a CTWA ad and starts a conversation, Meta waives conversation fees for 72 hours. — [thetechpad 2026 guide](https://thetechpad.com/blog/click-to-whatsapp-ads-guide-2026/) (secondary; verify against Meta pricing page)
- Endpoint encryption (Meta's implementation guide, Python sample):
  - Unwrap the AES key with RSA-OAEP, SHA-256 + MGF1(SHA-256).
  - Decrypt `encrypted_flow_data` with AES-GCM. The last 16 bytes are the tag, and the IV is the full 16 bytes.
  - Respond by encrypting with the same AES key and the IV **bitwise-inverted (XOR 0xFF)**, then base64 the ciphertext with the tag appended.
  — [Meta: Implement endpoints for Flows](https://developers.facebook.com/documentation/business-messaging/whatsapp/flows/guides/implementingyourflowendpoint)
- Pitfalls from third-party implementations:
  - Use a 16-byte nonce (AES-GCM with a 16-byte IV), not the stock 12-byte one.
  - A wrong IV flip yields error **421**. Return a blank 421 when an envelope cannot be decrypted, which triggers a key refresh.
  - `ping` health checks must return an encrypted health response.
  - One project wrongly describes the flip as byte-reversal. Meta's sample uses bitwise inversion.
  — [whatsapp-flows-server](https://github.com/guilhermejansen/whatsapp-flows-server); [waxum PR #134](https://github.com/imtaqin/waxum/pull/134); [Automation_Xpert PR #10](https://github.com/honeygarg389/Automation_Xpert/pull/10)
- There is a ready n8n template for encrypted Flows endpoints. — [n8n workflow 3973](https://n8n.io/workflows/3973-create-secure-interactive-applications-with-whatsapp-flows-end-to-end-encryption/)
- Completion benchmarks (vendor claims, no methodology):
  - Flows 60–80% vs web forms 15–25% — [Cliengo guide](https://guiawabusiness.cliengo.com/flows-captura-leads)
  - 40–70% higher completion than link-based forms; 50–65% booking completion vs 20–30% — [ChatDaddy](https://www.chatdaddy.tech/blog/whatsapp-flows)
  - Up to 60% lower abandonment in lead qualification — [EngageLab](https://www.engagelab.com/blog/whatsapp-flows)
- The only Meta-published case: Engelife Construtora reports +26 points lead-qualification rate and 37% lower cost per qualified lead using Flows vs **manual** qualification. Results are self-reported. — [WhatsApp Business success story](https://whatsappbusiness.com/resources/success-stories/engelife-construtora-e-incorporadora/)
- Caution: high Flow completion can hide poor lead quality, and a holdout is needed to prove causation. — [Chatarmin](https://chatarmin.com/en/blog/whats-app-marketing-leads)

### Inferences
- **Recommended pattern:** use one of two welcome-message options.
  - **Option A (preferred for speed):** the welcome message is an ice-breaker greeting with 3 prompts ("Book a demo", "See pricing", "I'm a BSP/agency"). The user's first message lands with the referral, and the bot immediately sends a multi-screen endpoint Flow.
  - **Option B:** the ad itself launches a **static single-screen Flow**, with name, company website, team size and use case as dropdowns plus an OptIn checkbox. Answers return in the `nfm_reply` webhook (`response_json`), and the AI agent continues the conversation for budget and timing.
  - A/B the two options in separate ad sets.
- **Qualification Flow screens** (endpoint-driven, three screens):
  - **Screen 1 "About you":** Name; Work email (optional); Company website or Facebook Page URL (needed for the MDF claim); Role (dropdown).
  - **Screen 2 "Your WhatsApp setup":**
    - Do you already use the WhatsApp Business API? (Yes with which BSP / No / Not sure)
    - Monthly conversations (dropdown bands, e.g. <1k / 1–10k / 10–100k / >100k)
    - Use case (sales / support / marketing / voice)
    - WABA ID and Business Manager ID (optional text inputs, with a "don't know" path)
  - **Screen 3 "Timing & budget":** Go-live timeline (≤30d / 1–3 mo / 3+ mo / exploring); Budget band in INR/month; an OptIn component for marketing follow-ups; a CalendarPicker/slot dropdown populated by the endpoint from Zoho Bookings availability.
  - The endpoint enables live validation, such as checking that the URL resolves and flagging a duplicate company, and lets the bot skip screens for disqualified answers.
- These fields map directly to past loss reasons. "Low budget" and "low priority" become the budget-band and timeline fields, captured **before** SDR time is spent.
- **Interactive-message fallback** for users who abandon the Flow: reply buttons and list messages, with the AI agent asking one question per turn.

### Gaps
- **[UNVERIFIED – prior knowledge]** Flow endpoint response must come within ~10 s. The `flow_token` should be a signed lead or session ID to correlate `nfm_reply` with the referral. Interactive reply buttons are max 3, title ≤20 chars. List messages are max 10 rows, row title ≤24 chars. Flow components include TextInput, TextArea, Dropdown, RadioButtonsGroup, CheckboxGroup, DatePicker, CalendarPicker, OptIn, Footer, If/Switch. Confirm all of these on Meta's Flows reference.
- Meta does not publish official Flow completion-rate benchmarks. All the numbers above are vendor claims.
- Whether Flow-in-welcome-message CTWA is available in India: one source cited an EU/Japan/Korea availability banner ([Chatbotscape](https://chatbotscape.com/glossary/click-to-whatsapp-ads)), which is unclear. Verify in Ads Manager for an India-targeted ad.

## 3. AI agent qualification design: question order, BANT-lite, drop-offs, re-prompts, human handoff, in-chat booking, WhatsApp voice calls

### Takeaway
- Run the qualification as a short BANT-lite sequence. The conversational agent covers Need/Use-case → Volume → Timeline → Budget band → Authority, with a Flow or buttons for structured answers.
- Score immediately, and hand "good" leads to an SDR in a shared inbox with a 15-business-minute SLA timer.
- Inside the window, nudge drop-offs with free-form messages. After the window, use approved templates, and only with opt-in.
- Use WhatsApp business-initiated calling (permission-gated) for the first human touch on hot leads.

### Cited Findings
- **Business-initiated calling** requires the user to grant a call permission to the business phone number. Meta's page was updated 26 Jun 2026. — [Meta: Business-initiated calls](https://developers.facebook.com/documentation/business-messaging/whatsapp/calling/business-initiated-calls)
- Permission/call limits differ by source:
  - 1 permission request per 24h and 2 per week. After a grant, 72h to place a call. — [Chakra HQ](https://chakrahq.com/article/whatsapp-cloud-api-calling-feature-details/amp/)
  - Up to 2 permission requests in 7 days if there is no response. After a grant, up to 5 connected calls per 24h during a 7-day permission period. — [Infobip](https://support.infobip.com/docs/whatsapp/whatsapp-business-calling/business-initiated-calling)
  - These are **conflicting**; verify on Meta's page.
- India is listed as supported for business-initiated calling. — [Infobip](https://support.infobip.com/docs/whatsapp/whatsapp-business-calling/business-initiated-calling)
- Outbound calling eligibility reportedly needs a messaging tier of ≥2,000. — [YCloud](https://www.ycloud.com/blog/whatsapp-business-calling-api)
- Error codes: 138006 = no approved permission; 138012 = 24h business-initiated call limit hit. — [Meta calling troubleshooting](https://developers.facebook.com/documentation/business-messaging/whatsapp/calling/troubleshooting/)
- The 72-hour free-entry window applies after a CTWA click. — [thetechpad](https://thetechpad.com/blog/click-to-whatsapp-ads-guide-2026/)
- Booking completion in Flows is reportedly 50–65% vs 20–30% via links (vendor claim). — [ChatDaddy](https://www.chatdaddy.tech/blog/whatsapp-flows)

### Inferences
- **Question order** (one per turn, buttons where possible; the AI agent extracts free text):
  1. Greeting plus the use case matching the ad, via buttons.
  2. "Are you on WhatsApp API today?" (current BSP = switching intent).
  3. Monthly volume band.
  4. Go-live timeline.
  5. Monthly budget band.
  6. Role / decision-maker.
  7. Company website or FB Page URL. Optional WABA ID / BM ID, with a "help me find it" path.
  8. Marketing opt-in.
  9. Offer a slot or a call.
- **Score:** e.g. A = timeline ≤30d AND budget ≥ threshold AND volume ≥ band 2; B = one missing; C = exploring / low budget.
- **Drop-off handling:**
  - After ~10 minutes of silence, one free-form nudge resuming at the last unanswered question.
  - At ~4h, a second nudge offering a call or slot.
  - At ~22h, a final in-window message (still inside the 24h customer-service window).
  - Within the 72h CTWA free-entry window, free-form is allowed only while the customer-service window is open. **[UNVERIFIED]** A 24h window resets on each user message, while 72h free entry concerns pricing. Confirm whether free-form is permitted between 24h and 72h without a user reply. Prior knowledge says no: a template is needed.
  - After the window: a utility or marketing template, only with captured opt-in.
- **Handoff:**
  - A or B score, or "talk to human" intent → assign the conversation in the Chat360 shared inbox to the SDR owner returned by Zoho assignment.
  - Post an internal note with the qualification summary. Start the SLA timer (business hours IST).
  - For A-leads with a granted call permission, the SDR places a WhatsApp voice call as the first touch.
  - Request the call permission in the bot's message right after scoring, so it is ready when the SDR picks up.
- **Booking inside WhatsApp:** a Flow screen with endpoint-populated slots from the Zoho Bookings or Google Calendar availability API. On submit, the endpoint creates the booking and returns a confirmation screen.

### Gaps
- No primary data on optimal question count or order for B2B SaaS qualification on WhatsApp. The design above is inference.
- Zoho Bookings availability/booking API endpoints were not researched in this session.
- WhatsApp calling pricing for India in 2026 was not found.

## 4. Zoho CRM integration: upsert, dedupe by phone, custom fields, assignment/round robin, SLA escalation, Analytics; glue options

### Takeaway
- Use `POST /crm/v8/Leads/upsert` with `duplicate_check_fields` set to a Phone field marked "Do not allow duplicate values".
- Let the `trigger` array fire workflow rules (SLA timers/escalations).
- Assign owners through a round-robin Assignment Rule applied on insert.
- Zoho Flow or n8n can glue the pieces, but since Chat360 owns the stack, a direct server-side call is simplest.

### Cited Findings
- v8 Upsert Records inserts or updates based on duplicate-check fields, and you can order the check with the `duplicate_check_fields` array.
  - Allowed fields: system-defined (e.g. Email for Leads) and user-defined **unique** fields ("Do not allow duplicate values" enabled), e.g. Phone.
  - If omitted, a default order applies.
  — [Zoho CRM v8 Upsert Records](https://www.zoho.com/crm/developer/docs/api/v8/upsert-records.html); [Deluge upsert v8](https://www.zoho.com/deluge/help/crm/upsert-record-V8.html)
- Community reports:
  - Passing `duplicate_check_fields` as a URL param stopped working; put it in the body.
  - The field must be unique in CRM for the dedupe to apply.
  - Max 100 records per upsert call (older post).
  — [Zoho community thread](https://help.zoho.com/portal/en/community/topic/problems-using-record-upsert-api-when-trying-to-check-for-duplicates); [Kaizen #56](https://help.zoho.com/portal/en/community/topic/kaizen-56-upsert-records-api?page=23)
- Automation triggers:
  - By default, API create, update or delete fires matching workflow rules, approvals and blueprints.
  - `"trigger": []` suppresses all of them.
  - `"trigger": ["workflow","approval"]` runs those but not blueprint.
  — [Kaizen #33](https://help.zoho.com/portal/en/community/topic/kaizen-33-triggering-workflow-rules-approvals-and-blueprints-via-zoho-crm-api?page=13); [Kaizen #148](https://help.zoho.com/portal/fr/community/topic/kaizen-148-trigger-in-records-apis)
- Assignment rules are configured at Setup > Automation > Assignment Rules.
  - The API lists them at `{api-domain}/crm/v4/settings/automation/assignment_rules`.
  - Rules can be executed while updating records via the Update Records API.
  - Verify the owner afterward with GET Records.
  — [Kaizen #88 Assignment Rules](https://help.zoho.com/portal/en/community/topic/kaizen-88-assignment-rules?page=54)

### Inferences
- **Lead upsert payload:** a body with `data[]` + `duplicate_check_fields: ["Phone"]` + `trigger: ["workflow"]`. Custom fields:
  - Source and ad: `Lead_Source="Meta CTWA"`, `CTWA_CLID`, `Ad_ID`, `Ad_Name`, `AdSet_Name`, `Campaign_Name`, `Ad_Headline`, `First_Msg_At`.
  - Qualification: `Qual_Score` (A/B/C), `Timeline`, `Budget_Band`, `Monthly_Volume`, `Current_BSP`.
  - MDF fields: `Company_Website`, `FB_Page_URL`, `WABA_ID`, `BM_ID`.
  - Consent: `Marketing_OptIn` + `OptIn_Timestamp` + `OptIn_Text_Version`.
  - SLA: `First_Human_Touch_At`, `SLA_Breached`.
  - CAPI: `CAPI_Lead_Sent_At`, `CAPI_Qualified_Sent_At`.
- Normalise phone to E.164 (`+91…`) before upsert, so that WhatsApp `wa_id` (no plus sign) and manual entries dedupe.
- **Two-stage write:**
  - On first message, upsert a minimal lead: phone, ad fields, `Qual_Status = "Chatting"`.
  - On qualification completion, upsert again with the answers and score.
  - Pass the assignment rule only on the qualified update, so A/B leads round-robin to SDRs and C leads go to a nurture owner.
- **SLA escalation:**
  - A Zoho workflow rule on `Qual_Score in (A,B)` with a time-based action at +15 minutes checks whether `First_Human_Touch_At` is empty. If so, it emails or Cliq-messages the SDR manager and reassigns.
  - Alternatively, a Blueprint with an SLA on the "New → Contacted" transition. Blueprint SLA/escalation configuration is not verified in this session.
  - Chat360's inbox writes `First_Human_Touch_At` back via API when an agent sends the first message or a call connects.
  - Business-minutes logic needs a business-hours calendar. Zoho workflow time triggers are wall-clock, so compute the business-minute due-time in Chat360 and write it into a `SLA_Due_At` datetime field that the workflow keys off.
- **Glue:** direct API from Chat360 is the simplest and lowest-latency option. Zoho Flow or n8n are good for the CAPI back-sync on Zoho stage changes: Lead converted → Deal won → Purchase event.
- **Zoho Analytics:** sync CRM Leads/Deals and build a funnel by `Campaign_Name/AdSet_Name/Ad_Name`: chats → qualified (A/B) → meetings booked → deals → won, with median `First_Human_Touch_At − First_Msg_At`.

### Gaps
- **[UNVERIFIED – prior knowledge]** The Insert Records API accepts a `lar_id` key (lead assignment rule ID) in the request body to apply an assignment rule on insert. Its availability on **upsert** in v8 could not be confirmed. Zoho round-robin is configured inside the assignment rule ("Round Robin" among users/roles), which is not verified via a live source.
- Zoho API rate/credit limits for the edition Chat360 uses were not researched.
- Blueprint SLA/escalation specifics and Zoho Bookings APIs were not researched.

## 5. Conversions API for Business Messaging (CAPI-BM) and feeding quality back to Meta

### Takeaway
- Send server-side events to a **dataset linked to the WABA** with:
  - `action_source: "business_messaging"`
  - `messaging_channel: "whatsapp"`
  - the un-hashed `ctwa_clid` in `user_data`
  - the WABA ID (or `page_id` in older guides)
- `LeadSubmitted` and `Purchase` are the confirmed event names. Whether a separate "QualifiedLead" event is accepted for WhatsApp was **not confirmed**.
- Practical constraints: send within 7 days of the click; one event per ad-event per vendor docs.

### Cited Findings
- Required core fields: `ctwa_clid` (from the referral) + `action_source=business_messaging`. `messaging_channel: whatsapp` identifies the channel. — [CustomerLabs](https://www.customerlabs.com/blog/how-to-connect-ctwa-chats-to-ad-campaigns-and-crm/); [metricfixer](https://metricfixer.com/publications/analytics-conversion-tracking/track-click-to-whatsapp-ads-campaign-ad-creative-without-website)
- Meta's **Automatic Events API** (for embedded-signup / tech-provider partners) example uses `"event_name": "LeadSubmitted"` with `action_source: business_messaging`, `messaging_channel: whatsapp`, `ctwa_clid` inside `user_data`, and a `messaging_outcome_data` block with `outcome_type: automatic_events`. It also shows a `Purchase` event shape. — [Meta: Automatic Events API](https://developers.facebook.com/documentation/business-messaging/whatsapp/embedded-signup/automatic-events-api)
- Dataset and IDs:
  - Events go to a dataset tied to the WABA, not the website pixel.
  - `POST` to the WABA's dataset edge returns the linked dataset, creating it if none exists.
  - The payload carries the WABA ID instead of the Page ID.
  — [oussch702/whatsapp-conversions-api](https://github.com/oussch702/whatsapp-conversions-api)
  - **Conflict:** an older Stape example uses `page_id` ([Stape](https://stape.io/news/whatsapp-conversion-api)), and AWS's Purchase example includes `whatsapp_business_account_id` in `user_data` ([AWS End User Messaging Social](https://docs.aws.amazon.com/social-messaging/latest/userguide/conversions-api.html)) while Meta's automatic-events example omits it.
- Meta accepts only a short list of event names for business messaging, and generic "Lead" is reportedly **not** on it. — [oussch702/whatsapp-conversions-api](https://github.com/oussch702/whatsapp-conversions-api)
- respond.io:
  - The event must be sent within **7 days of the ad click**.
  - Only **one CAPI event per ad event**.
  - It auto-includes the CTWA click ID.
  - It covers Leads and Purchases across WhatsApp, Messenger and Instagram.
  — [respond.io: Send Conversions API Event](https://respond.io/help/workflows/step-send-conversions-api-event)
- Interakt lets businesses define conversion points ("Lead Qualified", "Purchase Completed") with a conversion deadline measured from CTWA conversation start, so Meta optimises on real conversions. — [Interakt CTWA launcher](https://www.interakt.shop/resource-center/click-to-whatsapp-ads-launcher/); [Interakt CAPI setup](https://www.interakt.shop/resource-center/conversions-api/)
- The purchase-optimization goal reportedly appears only after **≥10 purchase events in the previous 7 days**. — vendor claim surfaced via search ([Woztell](https://support.woztell.com/portal/en/kb/articles/wa-conversion-flow) / [Interakt](https://www.interakt.shop/resource-center/conversions-api/))
- Change the generic default `action_source: "website"` for CTWA events. — [metricfixer](https://metricfixer.com/publications/analytics-conversion-tracking/track-click-to-whatsapp-ads-campaign-ad-creative-without-website)
- Infobip documents "Meta Ads Reporting for Business Messaging" as a BSP integration pattern. — [Infobip docs](https://www.infobip.com/docs/integrations/meta-ads-reporting-for-business-messaging)
- **Recommended event mapping for Chat360:**
  - `LeadSubmitted` = AI agent scores A/B, or the Flow completes with the required fields. This is the quality gate, so it should **not** fire on every chat.
  - `Purchase` with `value`/`currency=INR` = deal won.
  - Avoid using `LeadSubmitted` for raw chats. Guides advise sending it only after a real qualifying action. — [AsisteClick 2026 guide](https://asisteclick.com/en/blog/click-to-whatsapp-ads-ctwa-conversion-2026/)

### Inferences
- **Volume problem:** 9 wins over ~2,108 leads historically means a Purchase signal is far too sparse to optimise on. The ≥10 purchases per 7 days threshold is unreachable on $23k in 6 weeks. Optimise toward **LeadSubmitted defined as "qualified A/B"** (perhaps ~15–25% of chats). Report deals and wins via CAPI for measurement only.
- **Window constraint:** 2,108 → 362 deals happened over an unknown cycle. Deal-won events usually arrive after the 7-day CAPI window and will be rejected or unattributed. Qualification must fire within minutes or hours of the chat.
- **Example payload shape** (field names per the sources above; confirm against the live reference):
  `POST https://graph.facebook.com/v{N}/{DATASET_ID}/events` with
  `{"data":[{"event_name":"LeadSubmitted","event_time":<unix>,"action_source":"business_messaging","messaging_channel":"whatsapp","user_data":{"whatsapp_business_account_id":"<WABA>","ctwa_clid":"<clid>"},"custom_data":{"lead_score":"A"}}],"access_token":"<system-user token>"}`.
  Store the event ID / send timestamp in Zoho to prevent double-sends, given "one event per ad event".
- **Chat360-specific option:** because Chat360 is a tech provider, its own WABA may be eligible for Meta's Automatic Events, which auto-detects LeadSubmitted/Purchase from chat content. That would conflict with manual CAPI events. Disable one or the other to avoid double counting **[inference; verify]**.

### Gaps
- No live confirmation of the **complete allowed event-name list** for business messaging (e.g. whether `QualifiedLead`, `InitiateCheckout`, `AddToCart`, `ViewContent` are accepted for WhatsApp). The Meta reference page was unreachable.
- No confirmed info on whether the Ads Manager "Maximise conversions" / "conversion leads" performance goal for Messaging (WhatsApp destination) is available in India for B2B lead events in late 2026, or on minimum event-volume thresholds for LeadSubmitted.
- Event Match Quality for business-messaging events: no source found. With `ctwa_clid` as a deterministic key, EMQ may be less relevant, but this is unconfirmed.
- No 2025–2026 changelog items on CAPI-BM were captured. The [WhatsApp changelog](https://developers.facebook.com/documentation/business-messaging/whatsapp/changelog) should be checked.

## 6. Data protection: phone storage, marketing consent, DPDP, and WhatsApp policy for CTWA-originated opt-in

### Takeaway
- A CTWA chat lets Chat360 reply in that conversation, but it is **not** a safe basis for later marketing templates. Capture an explicit, logged opt-in that names Chat360 and the purpose, inside the chat (Flow OptIn component or button).
- India's DPDP Rules were notified on 13 Nov 2025 with phased commencement. Consent-manager provisions apply around Nov 2026, and the core notice/consent duties around 13 May 2027.
- Build DPDP-grade notice and consent records now, during the campaign.

### Cited Findings
- WhatsApp policy (secondary sources):
  - Proactive promotional messages may go only to opted-in users.
  - The opt-in must name the business and the purpose.
  - A phone number in a CRM is not an opt-in.
  - A general opt-in is acceptable if it clearly says the user will receive WhatsApp messages from the named business.
  — [Infobip opt-in guide](https://www.infobip.com/blog/how-to-collect-whatsapp-business-opt-ins); [helo.ai](https://helo.ai/resources/blog/whatsapp-opt-in-complete-guide); [wetarseel](https://wetarseel.ai/whatsapp-business-api-opt-in-rules/)
- On CTWA, one blog says a user who messages from an ad is opted in to **that conversation**. Another advises adding an explicit opt-in prompt in the welcome flow for future marketing templates. — [messagecentral](https://www.messagecentral.com/blog/whatsapp-marketing-business); [auditsocials](https://www.auditsocials.com/blog/whatsapp-business-api-click-to-whatsapp-ads-compliance-guide-2026)
- Include an "Opt-out" quick-reply button in marketing templates and honour opt-outs. — [Whatsable](https://whatsable.app/blog/whatsapp-spam-policy-explained-for-businesses-in-2026)
- **[UNVERIFIED]** One source claims a Jan 2026 requirement for Business Verification plus a privacy-policy URL before template sending. — [gmcsco](https://gmcsco.com/your-simple-guide-to-whatsapp-api-compliance-2026/)
- DPDP Rules 2025:
  - Notified 13 Nov 2025 (G.S.R. 846(E); commencement G.S.R. 843(E)), with phases at immediate, 12 months and 18 months.
  - Consent Manager provisions apply around 13 Nov 2026.
  - Notice, consent, security safeguards, breach reporting and Data Principal rights apply around 13 May 2027.
  — [TCSA](https://www.tcsa.in/resources/dpdp-rules-2025-implementation-roadmap); [dpdpactindia timeline](https://www.dpdpactindia.com/timeline.html); [dcomply rules](https://dpdpa.dcomply.in/rules/)
  - **Conflicts:** one source gives 14 Nov 2026 / 14 May 2027 ([vratex](https://www.vratex.com/dpdp-act/dpdp-rules-2025-timeline)). Sources also disagree on whether penalties bite from Nov 2026 or May 2027 ([consentos](https://consentos.in/learn/dpdp-compliance-timeline/)).
- Consent notice elements per Rule 3: identity, data types, purpose, withdrawal method, rights, grievance mechanism, retention period, third-party sharing. — [Consently](https://www.consently.in/blog/dpdp-rules-2025-implementation-timeline-india); [PrivyByIDfy](https://www.privybyidfy.com/blog/dpdp-compliance-guide-2026-what-indian-enterprises-must-do-before-may-2027)

### Inferences
- **Opt-in copy** (Flow OptIn component or button). Draft: "Yes, Chat360 can send me product updates, offers and event invites on WhatsApp. I can reply STOP anytime. Privacy notice: chat360.io/privacy". This is a draft for legal review.
- Store `Marketing_OptIn`, a timestamp, the `wamid` of the consent message, and an opt-in text version ID in both Chat360 and Zoho.
- Keep **service** follow-ups (SDR replies about the inquiry) separate from **marketing** follow-ups (nurture templates), and only send the latter to opted-in leads.
- **Third-party sharing:** CAPI sends `ctwa_clid` (and optionally hashed phone or email) to Meta. Disclose "advertising measurement with Meta" in the privacy notice.
- **Minimisation:** do not send phone or email to Meta when `ctwa_clid` is present. Set a retention period (e.g. 24 months for leads that never progress), and give DSAR/withdrawal handling a Zoho workflow.
- **MDF identifiers:** WABA ID and BM ID identify businesses, not individuals, which is low risk. Store them in Account fields once the lead converts.

### Gaps
- Meta's actual WhatsApp Business Messaging Policy text on CTWA-originated opt-ins could not be fetched. All policy statements here are secondary.
- No legal analysis was found of how DPDP "consent" maps to WhatsApp marketing opt-ins, or of whether B2B contact data at work numbers is treated differently.

## 7. Monitoring: response-time tracking, chat-to-qualified dashboards by ad, alerting

### Takeaway
- Monitor on two planes:
  - Meta's ad-side metrics: `onsite_conversion.messaging_conversation_started_7d`, plus CAPI-reported LeadSubmitted/Purchase per ad.
  - Chat360/Zoho first-party funnel fields, keyed on ad ID, with SLA alerts on business-minute timers.

### Cited Findings
- Ad insights per ad are available via `/{ad-id}/insights`. Messaging conversations started = `onsite_conversion.messaging_conversation_started_7d`; new messaging conversations = `onsite_conversion.messaging_first_reply`. — [Meta ads-action-stats reference](https://developers.facebook.com/docs/marketing-api/reference/ads-action-stats/); [Meta Insights API](https://developers.facebook.com/docs/marketing-api/insights/v2.5)
- A high Flow completion rate can mask poor lead quality and agent load, so use holdouts to prove causation. — [Chatarmin](https://chatarmin.com/en/blog/whats-app-marketing-leads)

### Inferences
- **Core KPIs by Campaign / AdSet / Ad (daily):**
  - Spend; Meta "conversations started"; Chat360 chats with referral.
  - Capture rate = Chat360 referral chats / Meta conversations started. Target ≥95%; a gap signals webhook loss.
  - % that answered Q1; qualification completion %; A/B/C mix; cost per A/B lead.
  - Meetings booked; meetings held; deals; won; plus Meta-reported LeadSubmitted, to reconcile with CRM.
- **SLA KPIs:**
  - Median and p90 business-minutes from qualification to first human touch.
  - % of A/B leads touched within 15 business minutes.
  - Breaches by SDR.
- **Alerts** (Cliq/Slack via Zoho workflow or n8n):
  1. An A/B lead untouched at +10 business minutes goes to the SDR; at +15 it goes to the manager and the lead is reassigned.
  2. Hourly referral-capture rate drops below 90%.
  3. CAPI error rate above 0, or zero LeadSubmitted sent in 4h while chats are greater than 0.
  4. Flow endpoint 421 or error spikes, or latency near the timeout.
  5. An ad with ≥30 chats and 0 A/B leads should be flagged for pause, which addresses the "low budget/low priority" pattern.
- Reconciliation: Meta's 7d-attributed LeadSubmitted counts will be lower than CRM A/B counts because of the 7-day window and organic chats. Use CRM as the source of truth for MDF reporting, and attach `Ad_ID` + `CTWA_CLID` per lead as proof.

### Gaps
- No published practitioner benchmarks were found for CTWA B2B SaaS chat-to-qualified rates or SDR speed-to-lead on WhatsApp specifically.
- Zoho Analytics prebuilt CRM connector refresh frequency, which matters for near-real-time SLA dashboards, was not researched. Alerts should therefore run off workflow rules or Chat360 events, not Analytics.
